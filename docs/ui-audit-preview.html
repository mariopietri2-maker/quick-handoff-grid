Native Apps UI/UX Audit Preview

Date: 2026-08-07

Driver app (native-driver)

Screen/component: Support Ticket Chat Dialog

Symptom: Long message threads could become hard to use on smaller displays and around keyboard open/close transitions.

Root cause: Scroll area used Column + verticalScroll in a full-screen dialog, and inset modifier ordering could produce inconsistent bottom spacing.

Fix summary: Switched thread container to LazyColumn, set explicit dialog dismiss behavior, and reordered insets to apply navigationBarsPadding() before imePadding().

Before/after notes: Before, thread composition/insets were more brittle under IME transitions. After, thread remains scrollable and spacing is stable with keyboard/system bars.

Screen/component: Ops list screen

Symptom: Last list rows and CTA area could sit too close to or under system navigation on some devices.

Root cause: Root screen container lacked navigation bar inset padding.

Fix summary: Added navigationBarsPadding() to the root OpsScreen container.

Before/after notes: Before, bottom content risked collision with nav area. After, content is lifted above bottom system UI.

Screen/component: Support Center root layout

Symptom: Inset behavior around keyboard + bottom system UI could feel inconsistent across devices.

Root cause: IME and navigation bar paddings were applied in the less stable order.

Fix summary: Reordered modifier chain to navigationBarsPadding() then imePadding().

Before/after notes: Better consistency when keyboard appears while preserving existing behavior.

Customer app (native-customer)

Screen/component: Store Menu screen + floating Cart bar

Symptom: Menu list relied on a hardcoded bottom spacer and could still feel overlap-prone with floating cart CTA.

Root cause: Manual Spacer(100.dp) workaround instead of structured list content padding.

Fix summary: Replaced spacer hack with dynamic LazyColumn contentPadding tied to cart visibility.

Before/after notes: Before, static spacing could be too much or too little. After, bottom spacing is explicit and flow-safe when cart CTA is present.

Validated flows checklist

  • Driver: Support chat dialog opens, dismisses, scrolls, and send CTA remains usable during keyboard transitions.
  • Driver: Ops list remains navigable and bottom actions are visible above system navigation.
  • Driver: Support center root insets stay stable with keyboard/system bars.
  • Customer: Menu list -> add item -> floating cart bar path no longer relies on spacer hacks and avoids bottom overlap.
  • Customer: Navigation between Home/Menu/Cart remains unchanged.

Known limitations / future improvements

  • No screenshot bundle included in this preview file.
  • A wider pass can still convert additional long verticalScroll screens to LazyColumn for stronger performance consistency.

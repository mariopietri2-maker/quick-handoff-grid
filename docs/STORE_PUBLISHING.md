# Store publishing — Play Store + App Store

Fresh ships **two** apps:

| App | Bundle / application ID |
|---|---|
| Fresh Customer | `com.freshdelivery.customer` |
| Fresh Driver | `com.freshdelivery.driver` |

Debug APKs (`./scripts/build-apks.sh`) are for sideload / beta testing only — **Play Store rejects unsigned/debug APKs**. Use **signed `.aab`** (Android App Bundle) for Play.

---

## Google Play (signed AAB)

### One-time setup

1. Create a [Google Play Console](https://play.google.com/console) developer account.
2. Create two apps (Customer + Driver) with package names above.
3. On this machine (or CI secrets), generate **upload keystores**:

```bash
chmod +x scripts/setup-play-signing.sh scripts/build-store-aabs.sh
./scripts/setup-play-signing.sh
```

This writes (gitignored):

- `mobile-signing/fresh-customer-upload.jks`
- `mobile-signing/fresh-driver-upload.jks`
- `mobile-signing/key.properties`

**Back these up offline.** If you lose the upload key and are not enrolled in Play App Signing recovery, you cannot update the app.

4. Build signed bundles (includes BG location, FCM sounds, Firebase when present):

```bash
APK_VERSION_CODE=7231500 APK_VERSION_NAME=1.0.7231500 ./scripts/build-store-aabs.sh
# → store-bundles/fresh-customer-release.aab
# → store-bundles/fresh-driver-release.aab
```

`versionCode` must increase for every Play upload.

5. Play Console → each app → **Internal testing** (recommended first) or **Production** → **Create release** → upload the `.aab`.
6. On first upload, enable **Play App Signing** (Google keeps the app signing key; you keep the upload key).

### Checklist before review

- [ ] Store listing (GR/EN), screenshots, feature graphic, privacy policy URL
- [ ] Content rating questionnaire
- [ ] Target API / Data safety form
- [ ] Customer + Driver: declare location (incl. background) use
- [ ] Stripe **live** keys on Vercel + Supabase edge secrets
- [ ] Turn off debug WebView (`build-store-aabs.sh` already omits `webContentsDebuggingEnabled`)

### What ships in the AAB (parity with debug APKs)

- Capgo background geolocation (customer: active order; driver: online)
- Custom notification sounds (`customer_notify` / `fresh_delivery`)
- PushNotifications + Firebase `google-services.json` when present under `mobile-signing/firebase/`
- No WebView debugging

## Apple App Store (iOS)

iOS project folders are generated by Capacitor (`ios-customer`, `ios-driver`).  
**This Linux CI can sync + zip the Xcode projects, but cannot archive or sign an IPA** — that requires a Mac with Xcode and your Apple Developer team.

### Prepare projects (Linux or Mac)

```bash
IOS_VERSION_NAME=1.0.7231500 IOS_BUILD_NUMBER=7231500 ./scripts/sync-ios-apps.sh
# → store-bundles/fresh-customer-ios-xcode.zip
# → store-bundles/fresh-driver-ios-xcode.zip
```

Sync applies:
- Web assets for each flavor
- Location + background location privacy strings (customer + driver)
- `UIBackgroundModes`: `location`, `remote-notification`
- Push entitlements (`aps-environment` = production)
- Marketing / build version aligned with Android

### On a Mac (required to upload)

1. Unzip the archives (or clone the repo and re-run sync).
2. Register bundle IDs in [Apple Developer](https://developer.apple.com/account/resources/identifiers):
   - `com.freshdelivery.customer`
   - `com.freshdelivery.driver`
3. Create both apps in [App Store Connect](https://appstoreconnect.apple.com).
4. For each app:

```bash
open ios-customer/App/App.xcodeproj
# Capacitor 8 uses Swift Package Manager — Xcode resolves packages on first open.
# If a Podfile exists instead: cd ios-customer/App && pod install && open App.xcworkspace
```

5. Signing & Capabilities → your Team. Enable **Push Notifications** and **Background Modes** (Location updates + Remote notifications).
6. Product → **Archive** → **Distribute App** → App Store Connect.
7. Repeat for `ios-driver`.
8. TestFlight → internal testers before production.

Optional: drop `GoogleService-Info.plist` into each `App/App/` for FCM (see `docs/FIREBASE_PUSH.md`).

### What we cannot do from this cloud agent alone

| Step | Why |
|---|---|
| Create your Play / Apple developer accounts | Requires your identity + payment |
| Upload to stores | Needs your console login |
| Sign iOS IPA | Requires macOS + Xcode + your Apple certs |
| Guarantee review approval | Store policies / screenshots / legal |

Beta sideload APKs remain at GitHub release `mobile-apks-v1` and `/download` for testers.  
Play upload bundles: GitHub release `play-store-aabs-v1`.  
iOS Xcode project zips: GitHub release `ios-xcode-projects-v1`.
